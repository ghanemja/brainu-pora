# ATP — Agentic Training Platform

**This document is the binding contract for the ATP build.** Every schema, window
global, component signature, and file boundary below is normative. Builders
implement exactly this; reviewers verify against this.

ATP reshapes Brain University into a **training assistant and certification
system for AI agents**, modeled on human educational progression. The existing
BU learning experience remains as the **Human view**; the new **Agent view**
is the Agent University. A top-bar toggle switches between them.

Design goal #1: **interpretability and trust**. A human must always be able to
see *why* an agent is certified at a given level and *how* it will perform.
Every badge is one click away from its evidence.

---

## 1. The 7-layer pyramid

| Layer | Title | Modeled on | Agent meaning |
|---|---|---|---|
| L1 | K1–K12 Skills | Phillips Exeter Academy K–12 sequence (Harkness, problem-based) | Core competencies: arithmetic/symbolic manipulation, reading comprehension, composition, scientific method, chronological reasoning |
| L2 | 4-Year College | MIT undergraduate curriculum (GIRs + majors: Course 6, 8, 18, 2) | Undergraduate breadth: each MIT course maps to an agent competency track |
| L3 | Master's / PhD | MIT graduate programs (quals + research) | Graduate depth: qualifying exams + a novel research artifact w/ replication |
| L4 | World Knowledge Engines | Wikipedia, math engines (CAS/SymPy-class), physics engines (MuJoCo/FEA-class) | Internet-scale knowledge + tool-use: retrieval fidelity, engine interop |
| L5 | Company Knowledge | Internal docs, contracts, playbooks, tribal knowledge | Org-specific mastery; certification requires SME sign-off + per-item provenance |
| L6 | Domain Knowledge | Ops, Finance, Bio, Physics, Math | Domain badge: engine-interaction hours + company domain experience + badge exam |
| L7 | Domain Expertise | PhD-level + company domain mastery | The **Agent-Domain-Expert**: capstone = real company problem solved end-to-end, committee verdict |

Beneath the pyramid: **infrastructure foundation** — Local LLM (Gemma 5.5) on
H100 cluster / Spark cluster. Rendered as the slab everything rests on.

**Career stage overlay** (orthogonal to layer):
`early` = ≤L3 or <6 months in service · `mid` = L4–L5 or 6–18 months ·
`late` = L6–L7 and >18 months. Displayed as "early-career expert" etc.

**RL reward weighting** (heaviest at L5–L7, normalized):
`{L1:0.04, L2:0.06, L3:0.08, L4:0.12, L5:0.20, L6:0.24, L7:0.26}`
HITL reward delta = `signal × 0.2 × (weight[layer] / 0.26)`, logged append-only
(auditable) to `data/sessions/atp_hitl.jsonl`.

## 2. The ATP standard (badge label spec)

- **Citable sentence:** `"{Agent} is an ATP L{n}-certified agent in {Domain}."`
  e.g. *"Gemma is an ATP L4-certified agent in Math."*
- **Machine label:** `ATP-L{n}.{domain-slug}@{version}` e.g. `ATP-L4.math@2026.1`
- **Meaning is one click away:** every rendered badge opens a panel showing the
  level definition, exam blueprint, rubric, pass criteria, and the awardee's
  evidence trail.
- **Standard principles** (surfaced in UI): (1) evidence-linked — no badge
  without a traversable evidence trail; (2) judge/candidate separation — the
  grading model family must differ from the candidate's; (3) reproducible —
  every exam records seed, temperature, run count, harness version; (4) failure
  transparency — failure modes published alongside passes; (5) revocable —
  certification decays without reinforcement and is revoked on sustained
  quality collapse (EWMA below threshold), with the revocation on the record.

## 3. Data contract — `window.ATP_DATA`

New file `design/atp_data.js` (generated by `scripts/build_atp_data.py` from
`atp/seed.py` — **do not hand-edit**). Synchronous IIFE assigning

    curriculum: [ {track, items:[{code, name, competency}]} ],
    graduation: { requirements:[str], certIds:[str] },
    agentIds: [str]                                 // agents currently AT this layer
  } ],
  AGENTS: [ {

## 4. Python layer

- `atp/__init__.py` — exports `get_data()`.
- `atp/seed.py` — `build_seed() -> dict` returning the full ATP_DATA dict
  (single source of truth; pure data, no I/O).

  `read_hitl(limit=100)`.
- `scripts/build_atp_data.py` — emits `design/atp_data.js`: header comment
  "Generated by scripts/build_atp_data.py — do not edit by hand", IIFE with
  `JSON.dumps` payload + appended plain-JS helper functions.

## 5. API surface

`api/atp.py` — `router = APIRouter(prefix="/atp")`:
`GET /atp/data` (full blob) · `GET /atp/agents` · `GET /atp/agents/{agent_id}`
· `GET /atp/certs` · `GET /atp/certs/{cert_id}` · `GET /atp/standard`
· `GET /atp/marketplace` · `GET /atp/hitl` (log, latest first)
· `POST /atp/hitl` body `{agentId, layer, signal, reason, rater}` → appended
event. 404s use HTTPException. Wire-up: `api/server.py` adds
`from api.atp import router as atp_router; app.include_router(atp_router)`.
Auth: inherits the default bearer gate (no PUBLIC_PATHS changes).
`Dockerfile`: add `COPY atp/ ./atp/` beside the other COPY lines.

`design/api.js` — add methods: `atpData()`, `atpAgents()`, `atpAgent(id)`,
`atpCerts()`, `atpStandard()`, `atpMarketplace()`, `atpHitl(payload)`,
`atpHitlLog()`. Read methods fall back to `window.ATP_DATA` slices when the
backend is unreachable (same pattern as `trailhead()`); `atpHitl` POST returns
`{ok:false, offline:true}` on failure.

## 7. Expert composition & train-to-order

Marketplace is not a static catalog: every unmet request is a demand signal
that produces a new certified asset. ATP owns the standard (exams) **and** the
supply (training). Build-order invariant: curriculum map → exam blueprints per
track → registry/matching → commission wizard — blueprints must exist before
commissioning has anything to grade against (in seed terms: every composable
track's `graduation.certIds` resolve to real CERTS).

### 7.1 Data (additions to `window.ATP_DATA`)

```js
COMPOSE: {
  majors: [ {course:'6', name:'EECS',
             concentrations:[ {id:'6-3', name:'Computer Science',
                               competencies:[str],      // skill names this track demands
                               certIds:[str]} ]},       // blueprints that grade it
            ...Course 8, 18, 2 ],
  badges: [ {certId, domain} ],          // the L6 badge set
  packs:  [ {id, name, summary, policyIds:[str]} ]   // L5 company knowledge packs
},
EXPERT_REQUESTS: [ {
  id:'req-001', ts, major, specialty, badgeIds:[str], packId|null,
  layers:[int], corpora:[str],           // e.g. ['OCW 8.02','OCW 8.03']
  status:'matched'|'gap'|'training'|'certifying'|'listed',
  matchedAgentId|null,
  gap: {covered:[skillName], missing:[skillName], coveringAgentIds:[str]} | null,
  pipeline: [ {stage:'requested'|'corpus-mapped'|'fine-tuning'|'certifying'|'listed',
               ts|null, done:bool} ],
  resultAgentId|null                     // set when status==='listed'
} ]
```

`AGENTS[*]` gains required field
`provenance: {origin:'pre-existing'|'commissioned', corpora:[str], requestId|null}`.
Rendered as a chip: `trained-to-order · corpus: OCW 8.02/8.03` next to the
badge row. **Commissioned experts are certified identically — same blueprints,
same evidence trail, no separate trust tier.** Career overlay rule: a
commissioned expert starts `early` career stage regardless of layer until it
accrues L5 company-interaction evidence.

New helper in `atp_data.js`:
`matchExperts({course, concentrationId, badgeIds, packId}) ->
 {exact:[agentId], partial:[{agentId, covered:[str], missing:[str]}]}` —
exact = agent whose skills cover all track competencies AND holds the badge
certs AND (packId ? bound to pack policies : true); partial ranked by coverage.

Seed: ≥4 EXPERT_REQUESTS covering every status, incl. one `listed` whose
`resultAgentId` is a commissioned agent in AGENTS ("Gemma-Physics-OCW":
provenance corpora `['OCW 8.02','OCW 8.03']`, holds the L3 physics cert,
early-career, marketplace-listed). Every pre-existing agent gets
`provenance.origin:'pre-existing'`.

### 7.2 API + store

`atp/store.py`: `append_request(payload) -> request` (computes status via the
same matching rule against seed agents, builds pipeline stages, appends to
`data/sessions/atp_requests.jsonl`), `read_requests(limit=100)`.
`api/atp.py`: `GET /atp/requests`, `POST /atp/requests` body
`{major, specialty, badgeIds, packId}`.
`design/api.js`: `atpRequests()`, `atpCompose(payload)` — offline fallback:
run `window.ATP_DATA.matchExperts` client-side and return a local
request object marked `{offline:true}`.

### 7.3 UI (marketplace screen owns this)

**Compose Expert wizard** — stepper: ① major (MIT catalog) → ② concentration
→ ③ L6 domain badge(s) (multi-select) → ④ L5 company pack (optional) →
**result panel**, one of:
- **Exact match** → listing card, trust metrics up front, License CTA.
- **Partial match** → gap analysis on the skill graph: covered competency
  nodes vs missing ones (color-coded list + counts), best partial agents
  ranked by coverage, CTA "Commission the gap".
- **No match** → "Commission training" CTA.

Commission → creates request (via `BU_API.atpCompose`), renders
pipeline-progress UI driven by `status`/`pipeline` (requested → corpus-mapped
→ fine-tuning → certifying → listed), provenance-label preview, and the note
"certified via the same exam blueprints as every ATP agent". Marketplace also
gets: provenance chips on commissioned listings + a "Commissions" board
listing EXPERT_REQUESTS with status.

data access only through `window.ATP_DATA` helpers; charts are inline SVG.
