# Plan 03 — Mastery-aware traversal

**Status:** designed, not yet implemented
**Touches:** `agents/lesson_plan.py`, new module `agents/mastery.py`,
`agents/feedback.py`
**Estimated effort:** ~2 engineer-weeks

---

## Why

`plan_tour` currently picks the next stop by a combination of pagerank,
degree, and adjacency to visited nodes — it has no idea what the
learner already knows. The result is that a learner who already
understands `Gradient_Descent` still gets routed there because it's
high-pagerank in the cluster. Mastery-aware traversal turns the tour
from "topological walk" into "personalized curriculum."

## Scope

In:
1. `agents/mastery.py` — Bayesian Knowledge Tracing (BKT) state per (learner, node).
2. Per-stop "diagnostic micro-question" generation + scoring → updates BKT.
3. Replace `_pick_deepen` / `_pick_bridge` scoring functions with mastery-aware variants behind a feature flag.
4. Persist learner mastery state to `data/sessions/mastery/<learner_id>.json`.
5. Multi-objective score: `pagerank·w1 + novelty·w2 + adjacency·w3 + (1 - p_mastery)·w4 - difficulty_gap·w5`.

Out (deferred):
- Spaced repetition (FSRS) — separate roadmap item.
- DKT (deep knowledge tracing) — BKT is simpler and good enough for v1.
- Cold-start diagnostic quiz — separate roadmap item.

## API surface

```python
# agents/mastery.py

@dataclass
class MasteryState:
    learner_id:   str
    p_known:      dict[str, float]   # node -> p(learner already knows it)
    last_updated: dict[str, str]     # node -> ISO timestamp
    streak:       dict[str, int]     # node -> consecutive correct answers

# BKT parameters per-node (defaults; can be learned over time)
@dataclass
class BKTParams:
    p_init:    float = 0.10   # prior p(known) at first encounter
    p_learn:   float = 0.20   # p(known | previously unknown, just got exposed)
    p_slip:    float = 0.10   # p(wrong answer | known)
    p_guess:   float = 0.20   # p(right answer | unknown)

def load_state(learner_id: str) -> MasteryState: ...
def save_state(state: MasteryState) -> None: ...

def update_after_observation(state: MasteryState, node: str,
                              correct: bool, *, params: BKTParams | None = None) -> MasteryState:
    """Bayesian update of p(known | new observation)."""

def p_known(state: MasteryState, node: str, *, params: BKTParams | None = None) -> float:
    """Current estimated p(known) for the node."""
```

## Scoring change in `lesson_plan.py`

Today `_pick_deepen` scores by:

```python
score = adj * 5 + deg * 0.5 + prx * 100
```

New mix (behind `TOUR_MASTERY_AWARE=true`):

```python
score = (
      W_ADJ        * adj
    + W_DEG        * deg
    + W_PAGERANK   * prx
    + W_NOVELTY    * (1.0 - mastery.p_known(state, node))
    - W_TOO_EASY   * max(0, mastery.p_known(state, node) - 0.85)
    - W_TOO_HARD   * difficulty_gap(state, node, G)
)
```

`difficulty_gap` looks at neighbouring nodes: if all neighbours are
high-mastery but this node is a giant jump in degree/centrality, it's
likely "too hard" — penalize.

## Micro-question generation

After each lesson stop, the player offers a 1-question check:
- Stem from the lesson's `key_ideas[0]`.
- Distractors generated by an LLM call seeded with the cluster's other concepts.
- Correctness → BKT update on that node.

If the learner skips the question, mastery is updated less
aggressively (treat as a weak negative observation).

## Persistence + privacy

- Per-learner JSON file. For multi-tenant, swap to a Postgres table keyed `(tenant_id, learner_id, node)`.
- Field `last_updated` is later used by the spaced-repetition layer.
- Mastery state is the learner's; surface an export button + a "reset everything I've learned" control.

## Acceptance checks

- [ ] A learner who answers 3 micro-questions correctly on `Backpropagation` sees their `p_known('Backpropagation')` rise from 0.10 → ≥0.80.
- [ ] Same learner starting a new tour at `Neural_Networks` no longer gets routed through `Backpropagation` (it's filtered out as "already known").
- [ ] A learner who answers wrong twice in a row gets routed *backward* to an easier prerequisite on the next stop.
- [ ] With `TOUR_MASTERY_AWARE=false`, traversal is byte-identical to the old behavior (regression guard).
- [ ] Per-learner state file <50KB even after 1000 observations.

## Risks

- BKT parameter mis-calibration: start with safe defaults, expose
  per-node overrides for high-traffic concepts.
- Cold-start: until the learner has any history, traversal degrades
  gracefully to the existing pagerank-based plan.
- Privacy: per-learner mastery is sensitive in a company context — ACL
  it the same way as the company knowledge it represents.
