# Pseudo-configuration

## Definition

A **pseudo-configuration** is an algebraic structure consisting of a pair $(Z, \delta)$ where:

- $Z$ is a combinatorial structure (typically a graph or pseudo-triangulation) containing vertices and darts (directed edges)
- $\delta$ is a discharge function or constraint system defined on elements of $Z$
- The structure may contain **identification requests**—pairs of elements $(e_i, f_i)$ that are constrained to map to the same image under homomorphisms

A **free homomorphic image** $(Z^\circ, \delta^\circ)$ of $(Z, \delta)$ respecting a set of identification requests $\{(e_1, f_1), \ldots, (e_k, f_k)\}$ is a homomorphic image that:

1. Satisfies all identification requests: $\phi^\circ(e_i) = \phi^\circ(f_i)$ for all $i$
2. Makes **minimal identifications** beyond those required—all other vertices and darts remain distinct unless forced to identify

This minimality property makes the free homomorphic image **unique up to isomorphism**.

## Key Equations

For a homomorphism $\phi: (Z, \delta) \to (Z_1, \delta_1)$ respecting identification requests, the universal property states:

$$\forall \text{ homomorphisms } \phi_1: (Z, \delta) \to (Z_1, \delta_1) \text{ respecting } S, \,\exists ! \, \phi^\circ_1: (Z^\circ, \delta^\circ) \to (Z_1, \delta_1) \text{ s.t. } \phi^\circ_1 \circ \phi^\circ = \phi_1$$

This is the **universal factorization property** of free objects.

For a **pseudo-configuration with identifications**, the structure is:

$$\text{PseudoConfig} = (Z^\backslash, \delta^\backslash) = \bigcup_i (Z_i, \delta_i) \sqcup \text{(special elements)}$$

where $\sqcup$ denotes disjoint union, and identifications form an equivalence relation generated by the identification requests.

## Physical Intuition / Derivation

### Motivation from Graph Theory and Discharging

Pseudo-configurations arise naturally in **discharging method** arguments in graph theory and combinatorics. When proving structural properties (e.g., planarity, colorability), one:

1. **Assigns charges** $\delta$ to graph elements based on local properties
2. **Discharges** (redistributes) charge along edges according to rules
3. **Combines multiple discharging rules** by embedding them into a common triangulation

The challenge: when multiple rules embed into the same structure, their boundary edges must "match up"—this matching is formalized as identification requests.

### Construction via Union-Find

The **iterative construction** of the free homomorphic image uses a **union-find forest**:

1. **Initialize**: Each vertex/dart in $Z$ is its own root in the forest
2. **Process queue**: For each identification request $(e_i, f_i)$:
   - Find roots $\text{root}(e_i)$ and $\text{root}(f_i)$
   - Union them into a single equivalence class
   - This may trigger cascading identifications (e.g., if $e_i$ and $f_i$ belong to faces that must match)
3. **Terminate**: When no more forced identifications remain
4. **Image elements**: The roots of the final forest become the vertices and darts of $Z^\circ$

This greedy approach **minimally closes the identification requests under structural consistency**.

### Why "Free"?

The term "free" invokes the **universal property** from category theory: $(Z^\circ, \delta^\circ)$ is the **initial object** in the category of homomorphic images respecting the identification requests. It contains no extraneous identifications.

## Common Mistakes / Pitfalls

### 1. **Confusing Pseudo-configurations with Quotient Structures**
**Mistake:** Treating $(Z^\circ, \delta^\circ)$ as simply $Z$ with identifications applied.

**Issue:** Quotients often introduce unwanted identifications due to transitivity. Free homomorphic images carefully minimize identifications, respecting only *forced* equivalences.

### 2. **Assuming Uniqueness of Construction Sequence**
**Mistake:** Believing the order of processing identification requests in the union-find affects the final result.

**Correct view:** The final structure $(Z^\circ, \delta^\circ)$ is unique up to isomorphism regardless of processing order; only intermediate states differ.

### 3. **Neglecting Structural Constraints During Identification**
**Mistake:** Identifying darts $(e_i, f_i)$ without ensuring the incident faces and vertices also form a valid configuration.

**Issue:** Identifications must be **closed under structural consistency**—the algorithm iteratively processes cascading forced identifications.

### 4. **Misapplying Degree Constraints**
**Mistake:** Imposing identification requests that violate the specified degree ranges $\delta$.

**Correct approach:** Identification requests must respect the discharge function; if $\delta$ constrains vertex degrees, identifications must preserve feasible degree sequences.
